## Next P1 work and exit decision

1. Configure `CRON_SECRET` and a frequent external scheduler in an isolated preview target, apply the additive resume migration only after remote history/schema reconciliation, then prove a crash-before-start row is swept without a user retry. Vercel Hobby cron frequency must not be assumed.
2. Verify the preview source SHA, worker registration, protected sweeper authorization, one real authenticated recovery loop, and sanitized receipts. Do not promote to production or mutate the two historical connected runs on local evidence.
3. If strict replay from a stream offset is required for P1 acceptance, add a server-controlled reconnect test that can assert `Last-Event-ID`; the browser test currently proves reconnection and durable rehydration, not that inaccessible request header.
4. Carry the pure-computation recompute boundary into the P2 worker authority: cache uniqueness gives one durable Atros result, but exactly-once execution across a process crash would require a stronger external-effect receipt protocol.

Architecture assessment: this is not a narrow request-only patch. The transactional outbox, service-only store contract, Workflow self-fence, typed verifier/Atros results, canonical question identity, preserved resume trigger, and deployed sweeper boundary are reusable by the P2 job/revision authority. It still does not create the v3 person revision authority, publication fencing, astrology-off guarantee, exactly-once external calculation execution, or final approved UI. Local browser recovery and Atros fault gates now pass; P1 remains open on deployed migration/scheduler/recovery proof.

## Scope and acceptance boundary

P3 is the `extract → match/countercontext → reconcile → compose → verify → publish` learning path described in the [phased plan](PHASED-IMPLEMENTATION-PLAN.md) and spec WP2. An ordinary authenticated chat message must create supported, revisioned personal understanding; a correction and counterexample must revise dependent content without erasing history. Acceptance requires provider/evaluation evidence, persistence/reload/new-chat behavior, visual review, and recovery evidence. P2's service-seeded projection fixture is not P3 proof.

## Minimum must-pass scenarios

1. C02/C04/C05: age-15 account, later challenge, unresolved meaning and chapter; reload then retrieve the same account and its source in a different chat.
2. C06/C07: productive solitude and a draining counterexample qualify the same working explanation; no diagnosis or fixed trait.
3. C08/C20: correction or rejected explanation changes active/dependent claims immediately while preserving inspectable history.
4. C01/C13/C14: name-only sparse person remains sparse; alternate caregiving history yields domain-relevant rather than mission/productivity boilerplate.
5. D03/D07/D10/D11: retry after commit/response loss, provider/verifier failure recovery, coherent revision swap, and same-command replay/conflict behavior.
6. A01–A05: personal-only, astrology-on, astrology-off transition, old mixed-chat context, and in-flight mode changes cannot leak astro-derived context into personal understanding.

Also satisfy C09–C12, D04–D06, and the complete acceptance corpus before P3 closure. Do not claim P3 acceptance from a single good narrative, test-only evaluator fixture, HTTP status, screenshot, or manually published candidate.

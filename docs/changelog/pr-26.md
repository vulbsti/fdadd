# Keep imported conversation bodies in R2

## Summary

Imported chats and documents were stored whole in
`person_import_items.messages` (jsonb) and `body`. The table is empty today,
but one heavy export can be larger than the rest of the database.

With the edge object store configured, each item's body is written to R2 at
a content address under the owner's prefix, and the row keeps the title,
dates, counts, dedupe key, the object key and a digest. Without the edge the
body stays in the row as before. Stacked on PR 25.

## Changes

- Migration `20261004120000_import_bodies_in_object_store.sql`: nullable
  `body_object` and `body_digest` on `person_import_items`.
- `src/lib/imports/bodies.ts`: store selection, `encodeImportBody` /
  `decodeImportBody`, `orphanedImportBodies`, `inBatches`.
- `src/lib/imports/store.ts`:
  - `addPendingItems` writes bodies first (8 at a time), then rows with
    empty `messages`/`body`; duplicate detection uses `body_digest`.
  - `loadImportFiles` reads each body from the store; rows saved earlier are
    read inline. A missing body throws: a workspace is never built with an
    item silently empty.
  - `sweepImportBodies` after confirmation and deletion removes bodies no
    row names, skipping imports still being read or reviewed.
- `src/lib/edge/client.ts`: `list(prefix)`.

## Testing

- `bodies.test.ts` (4 tests). Unit 268, typecheck, lint.
- Migration applied on staging.
- Not exercised end to end against R2: there is no hosted import journey.
  The Worker operations it uses (`put`, `get`, `list`, `delete` with a server
  capability) are covered by the PR 25 smoke test.

## Risk / rollback

- Removing the edge settings after bodies were stored makes those imports
  unreadable; workspace preparation then fails loudly for that person.
- Deleting a profile cascades its rows but leaves its stored bodies (the
  same is true of Pi checkpoints). A person-level purge is a follow-up.
- The raw export upload still goes to Supabase Storage (50 MB cap on the
  free plan) and is deleted after parsing, as before.

## Review focus

# Make the Pi workspace the only agent: persona, precomputed chart, session memory

## Summary

Production answered with a legacy planner loop that saw Atros results as
300-character snippets, rejected its own answers with an unexplained error,
and knew nothing of the person's chart. Staging ran Pi, but as a "coding
assistant" with an appended paragraph, recalculating dashas on every question
from an engine that left gaps between periods and numbered planet houses in a
different system from the ascendant.

This PR removes the legacy loop from code, tests and database, and makes Pi
the only runtime, including production. Pi gets a purpose-built system prompt
(understand the person; reason with hypotheses and discriminating evidence;
Vedic only; rectify only on real conflict), reads a chart calculated once at
birth setup, searches every past conversation, and keeps a theory of mind
that is revised per session only when evidence refines or breaks it.

## Changes

**Atros engine** (`vendor/atros`)
- Dasha periods at every level tile their parent exactly; mahadasha
  boundaries no longer drift (`dashas/antardasha.py`, `timeline.py`,
  `vimshottari.py`, `yogini.py`).
- Planet houses are whole-sign from the ascendant, so yogas and Bhava Chalit
  inputs follow (`ephemeris/kerykeion_adapter.py`). 18 new tests.
- `ATROS_ENGINE_VERSION` bumped to `0.1.0+aidoraa.20260928`.

**Calculation layer**
- `astro_profile_calculations` stores chart, sensitivity, the lifetime
  pratyantar timeline and 48 monthly transits per birth revision, computed
  by the birth-setup workflow (`src/workflows/astrologer-intake.ts`,
  `src/lib/astro/profile-calculations.ts`, `runAtrosBatch`).
- `src/lib/astro/calculations.ts` writes `chart-summary.md` (whole-sign
  houses, lordships, dignity, nakshatras, shadbala, Bhava Chalit
  differences, sensitivity), `dasha/timeline.md`, `dasha/now.md`,
  `transits.md`.
- `scripts/backfill-profile-calculations.mts` for existing profiles.

**Workspace**
- `history/`: every conversation as Markdown plus an index; excluded
  messages are replaced by a marker (`src/lib/astro/conversation-history.ts`).
- `notes/theory-of-mind.md` from `person_theory_of_mind`, dropped after a
  privacy change. Canonical files are read-only in the VM.
- New conversations in an existing chat start with their earlier turns.

**Pi runtime** (`runtime/pi`)
- `system-prompt.md` replaces Pi's coding preamble via `--system-prompt`;
  today's date and capability go in the addendum. Thinking level `high`.
- Skills: `chart-reading` (with Atros rectify references), `rectify`,
  `person-context`.
- Tools: Pi built-ins, `person_state` (capabilities only), `ask_person`
  (one focused question, run ends `waiting_for_user`), `recalculate`
  (hypothesis birth time → `astrology/hypotheses/<label>/` with a
  comparison). Removed `workspace_*` and `atros_*` tools.
- `fd-find`, `ripgrep`, `jq` installed before the network is sealed;
  `PI_OFFLINE=1`.

**Session reflection**
- `src/workflows/theory-of-mind-reflection.ts` and
  `src/lib/astro/theory-of-mind.ts`: after a conversation ends (another
  conversation starts or is written in, or 30 quiet minutes via the cron
  sweep), a high-reasoning call keeps the theory unchanged or rewrites it.

**Legacy removal**
- `astrologer-run.ts` 1438 → ~230 lines; deleted agent tools, context
  selection, finish proposals, budgets, verification, `ASTROLOGER_RUNTIME`
  and the production guard. `tools.ts` removed.
- Migration `20260928100100_drop_legacy_loop.sql` drops the legacy-only
  tables, RPCs, `astro_sessions.search` and `astro_agent_runs.plan_json`.

**Database** (`20260928100000_pi_only_agent.sql`)
- `astro_profile_calculations`, `person_theory_of_mind`, session reflection
  columns and RPCs, `worker_finish_pi_run` with an optional focused question.

## Testing

  221 passed.
- `npm run test:pi:workspace`: 14 passed. Release preflight: 15 passed.
- Local database suite (`scripts/test-p0-db.sh`): 204 passed across 8 files,
  including focused questions and reflection fencing.
- Atros: 18 new tests pass; upstream suite 508 passed against the vendored
  source.
- Staging Preview (migrations applied to staging): the owner's question
  "whats is my dasha in 2026…" answered from stored files with correct,
  gap-free dates, chart-specific lordships and placements, and a focused
  question with a control option; the session reflection wrote a theory of
  mind 21 s after a new conversation started.

## Risk / rollback

- Production now needs Vercel Sandbox and the Pi broker route. Apply both
  migrations to production and run the backfill before promoting.
- The drop migration is irreversible for the legacy tables (production holds
  1 context row, 3 cache rows, 3 quota rows; the rest are empty).
- Without `PI_BASE_SNAPSHOT_ID`, a person's first message takes about two
  minutes (VM install). Hobby snapshot storage is full until 2026-10-01.
- Roll back by reverting the merge and redeploying; the drop migration is
  the only part that does not revert.

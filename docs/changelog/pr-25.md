# Store Pi workspace files in R2 and stream live text through a Durable Object

## Summary

Pi checkpoint archives and file blobs were relayed to Supabase Storage in
1 MB base64 pieces through Vercel functions, and every streamed token went
runner, Vercel function, Postgres row, 800 ms Workflow poll, Workflow stream,
SSE function, browser.

This PR adds a Cloudflare Worker (`cloudflare/edge`) with an R2 bucket and a
Durable Object per run. With `EDGE_ORIGIN` and `EDGE_SIGNING_SECRET` set, the
sandbox stores each archive and blob in one request straight to R2, and
streamed text goes runner, Durable Object, browser. Without those settings
nothing changes. Receipts, run steps and the published answer stay in
Postgres, and the answer never depends on Cloudflare. Builds on PR 24.

## Changes

**Worker** (`cloudflare/edge`)
- `src/token.mjs`: HMAC capabilities (`run`, `watch`, `server`) and
  `authorizeObject`: a run writes only its own archives and its person's
  blobs, and reads any archive or blob of that person.
- `src/index.mjs`: `/o/<key>` on R2 (the write is rejected unless the bytes
  hash to the digest in the key, 50 MiB cap), `/admin/delete|list` for the
  server, and `RunStream`: ordered events, duplicate posts ignored, replay
  from any sequence, storage written at most every 2 s, cleared by alarm.
- `wrangler.jsonc`: staging and production environments, SQLite-backed class
  (required on the free plan).

**App**
- `src/lib/edge/client.ts`: config, token signing, server-side object calls.
- `src/lib/astro/pi-objects.ts`: `PiObjectStore` with Supabase and edge
  implementations. `migratingPiObjects` reads R2 first, falls back to
  Supabase and copies the object across on first use.
- `pi-store.ts`: all archive and blob I/O through the store;
  `writePiCheckpoint(…, { digest })` records a receipt for bytes the runner
  already stored; `readStoredPiCheckpointBytes`, `discardStoredPiCheckpoint`.
- Broker: `checkpoint/stored` (validate the stored bytes, then receipt; an
  invalid archive is deleted) and `restore/stored` (names the archive and
  makes sure its blobs are in R2).
- `pi-runtime.ts`: the sandbox firewall allows the Worker host for `/o/`
  (PUT, GET) and the run's `/runs/<id>/events` (POST), injecting the run
  capability; the VM never holds it.
- `runs/[runId]/live`: owner-checked endpoint returning the stream URL and a
  watch capability.
- `live-text.ts` and `AstrologerChat.tsx`: the browser reads text from the
  edge alongside the events route; both feed `applyRunEvent`, which drops
  repeated sequence numbers.

**Runner** (`runtime/pi/runner.mjs`)
- With `config.edge`: direct PUT of blobs and archives, direct GET on
  restore, live events posted to the stream every 250 ms when there is text.
  Tool and exit events still go to the broker. If the stream post fails the
  batch takes the broker path, as before.

## Testing

- `cloudflare/edge/src/token.test.mjs` (4), `pi-objects.test.ts` (7),
  `live-text.test.ts` (4). Unit 264, runtime 14, preflight 21, typecheck,
  lint.
- Smoke test against the deployed staging Worker: wrong digest 400, other
  person 403, no token 401, watch token cannot read objects or publish, live
  and replayed frames in order, late joiner gets the full history.
- Staging journey on this branch: every functional step passed with
  checkpoints and a blob written to R2 by the sandbox
  (`checkpoint/stored` 200). It failed only on a browser console error from
  the Worker's CORS preflight (the test adds Vercel bypass headers to every
  request); fixed by echoing requested headers and verified by preflight.
  After the provider's rate limit cleared, the full journey passed on this
  branch with R2, the live stream and the Pi base snapshot.
- The session route now reads the run before its messages, fixing a race
  that hid a finished answer in the chat.

## Risk / rollback

- Remove `EDGE_ORIGIN` or `EDGE_SIGNING_SECRET` from Vercel to return to
  Supabase Storage and the events route. Objects already in R2 would then be
  invisible: archives of finished chats would restore as a fresh session.
  Copy them back first if that matters.
- Free plan: 100k Worker and 100k Durable Object requests per day. Past
  that, stream posts fail and the runner falls back to the broker; object
  writes would fail the checkpoint, so watch usage as volume grows.
- A changed runner bundle means every person gets a fresh VM on first use.

## Review focus

- `authorizeObject` and the firewall rules in `pi-runtime.ts`.
- `checkpoint/stored`: validation happens on the exact stored bytes.
- `migratingPiObjects.exists` adopting older blobs before a restore.

## Not in this PR

- Replacing the Workflow poll loop with a completion hook. The loop now
